# Draft bug report for linkedin-mcp-server

Post at: https://github.com/stickerdaniel/linkedin-mcp-server/issues

---

**Title:** `search_jobs` returns empty `job_ids` on the new LinkedIn jobs search layout (4.21.0 and 4.22.0)

**Body:**

## Summary

`search_jobs` returns a populated `sections.search_results` text blob but an
**empty `job_ids` array**, so results cannot be passed to `get_job_details`.
Reproduced on **4.21.0 and 4.22.0**, so it does not look like a regression in
either release — LinkedIn appears to have changed the jobs search page.

## Reproduction

```
search_jobs(
  keywords    = '("DevOps" OR "Site Reliability" OR "SRE" OR "Platform Engineer" OR "Kubernetes")',
  location    = "Mumbai, Maharashtra",
  date_posted = "past_24_hours",
  sort_by     = "date",
  max_pages   = 1
)
```

## Actual

```json
{
  "sections": { "search_results": "54 results\n\nMumbai (80 km)\n..." },
  "job_ids": [],
  "references": { "search_results": [ /* 1 job ref, plus people/feed_post refs */ ] }
}
```

The text blob contains ~24 visible jobs. `job_ids` is empty. `references` mostly
contains `person` and `feed_post` entries rather than `job` entries.

## Expected

`job_ids` populated with one entry per result.

## What appears to have changed on LinkedIn's side

1. **URL redirect.** Server log shows navigation to `/jobs/search/` landing on
   `/jobs/search-results/`:

   ```
   Navigation to https://www.linkedin.com/jobs/search/?keywords=...&sortBy=DD failed
   (wait_until=domcontentloaded, error=TargetClosedError)
   current_url=https://www.linkedin.com/jobs/search-results/?currentJobId=4453065829&keywords=...
   ```

2. **New result-card markup.** Each card now renders the title **twice** and
   carries a `(Verified job)` label:

   ```
   Tech S And T - Cloud Infrastructure Engineer - ISR - Senior - GDSF02 (Verified job)
   Tech S And T - Cloud Infrastructure Engineer - ISR - Senior - GDSF02

   EY

   Mumbai (Hybrid)
   ```

3. **Date format changed** from `11 hours ago` to `Posted 11 hours ago`
   (both strings now appear).

4. **Numeric pagination** (`1 2 3 Next`) replaces the previous single-page
   marker.

5. A `currentJobId=<id>` parameter appears in the redirected URL, which may be a
   usable fallback for at least the first result.

## Versions tested

| Version | Result |
|---|---|
| 4.22.0 | text populated, `job_ids: []` |
| 4.21.0 | text populated, `job_ids: []` |

## Environment

- Windows 11, `windows-amd64-host`
- Installed via `uvx mcp-server-linkedin@latest`
- Transport: `streamable-http`
- Session valid — `get_my_profile` returns the full authenticated profile,
  including private analytics, so this is not an auth problem.
